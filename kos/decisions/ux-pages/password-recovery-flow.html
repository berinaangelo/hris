Forgot password / reset password — three recommendations

Two pages, one flow: the request page (enter your work email) and the page the emailed link lands on (set a new password). Both reuse login-page.html's exact chrome per option — same field markup, same icons, same Ink & Amber tokens — and the same inline-only validation timing. What's new here is the terminal states a recovery flow actually needs that login doesn't: a "link sent" confirmation, an expired-link state, and a "password updated" success screen, all built on the icon-circle confirmation pattern already used for the job application form's submitted state.

Not yet covered by a decision on file: whether the request page discloses if an email is on file. Shown here as the standard security-conscious wording — "if an account exists for that email…" — never confirming or denying, consistent with decisions/security-practices-checklist.md's spirit even though it doesn't spell this out. Link expiry is shown as 15 minutes, a placeholder pending an actual policy decision. Request-page email validation stays format-only ("enter a valid work email"), matching login's own error copy — it deliberately does not say "no account found," for the same non-disclosure reason.

Why this one

Recommended. A password reset is a stressed, task-focused moment — the person just wants back in. No brand panel competing for attention fits Hick's Law better here than it did on login: fewer visual choices on screen while someone is already annoyed at being locked out.

Best when

Consistent with login's own "safe default" reasoning — cheapest to build, and the terminal states (sent / expired / success) read cleanly in a single small card without a second panel to keep in sync.

Why this one

Chosen — reuses login-page.html's split panel outright rather than re-litigating layout per auth screen. Same panel, copy swapped to security reassurance instead of god moments, since there's no product value to sell mid lockout.

Best when

Every auth-adjacent screen reads as one system at a glance instead of each picking its own visual weight. Costs the same two-column responsive layout as login; the left panel's copy has to be kept security-accurate rather than roadmap-accurate.
