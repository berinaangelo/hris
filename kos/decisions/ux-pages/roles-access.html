Roles & Access

HR-Admin screen under Company, scoped down from a full "role management" UI per the plan's own "employee / manager / admin — three roles, not a permissions matrix" (kos/projects/hris/PLAN.md, backed by decisions/rails-pundit-for-authorization.md). Role definitions themselves aren't editable here — the three roles and what each can do are fixed and shown read-only. The only thing this screen does is change which of the three roles an employee holds.

What's editable vs. reference-only: the capability checklist at the top is a read-only comparison — disabled checkboxes, no Save button — since building an editable permissions matrix is explicitly out of scope. The roster below is where the actual, only action lives: changing one employee's access level via the same right-side drawer mechanic used across Payroll Run Detail / Rate Tables / Loan Ledger / Job Opening Form / Offboarding. A safeguard is modeled for the one real risk this screen introduces — removing the last remaining Admin would lock HR out of its own settings — demonstrated on Andrea Cruz, the only Admin in this data set. Roles & Access

Every employee holds exactly one of three fixed access levels. See what each one can do, and change who holds which.

The three access levels

Fixed for now — adding custom roles or a configurable permission matrix isn't in scope.

Employee 9 people

Everyone's default. Self-service only — own profile, own leave requests, own payslips and reviews.

Manager 3 people

Everything Employee has, plus the Team tab — approving their own direct reports and reviewing their team.

Admin 1 person

Full access, including the Company tab — People Directory, Payroll, Recruitment, Compliance, Reports, and this screen.
