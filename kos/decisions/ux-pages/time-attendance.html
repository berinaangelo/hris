Time & Attendance — Shift Templates + Attendance Records — three recommendations

The HR-Admin workspace under Company → Time & Attendance (decisions/ui/navigation-me-team-company.md), built against projects/hris/features/time-attendance/PLAN.md. That plan bundles two pieces under one feature: a short, company-maintained shift_templates list (name + start/end time) and a per-employee attendance list with a late/undertime flag. All three options below show the same data — what changes is only how the rarely-edited admin config (shift templates) and the frequently checked operational list (attendance records) share one screen.

Ahead of the backlog, on purpose: Time & Attendance is post-MVP, customer-dependent (build only if a target customer has a shift-based/hourly workforce) — this mockup exists to compare screen shapes ahead of build. Viewing persona: Andrea Cruz, HR Admin. 3 shift templates, 10 employees, today is Aug 22, 2026. Per decisions/ui/badge-system-four-categories.md, On time gets no badge (the default state) — a badge appears only for Late/Undertime (Caution) or Absent (Negative). Per the plan's own out-of-scope list: no biometric/geolocation punch validation (clock times shown are illustrative digital/manual entries), no rotating schedules or per-day overrides, no auto-feed into payroll OT/deductions, and no night-differential or holiday-pay computation — this is attendance tracking, not pay computation. All content shown is static, illustrative — this is a comparison mockup, not a wired form.
Added 2026-08-23, Option 3 (chosen) only: correction requests, the per-row manual-edit action, and the Attendance Settings card are new — see decisions/time-attendance-correction-request-and-manual-edit.md. Synced 2026-08-23 to the real backend that has since shipped for this scope — settings are live, Edit and Review each open a real drawer, and an Approval status column reflects the sign-off state. The separate Attendance Sign-offs inbox page stays unbuilt in this mockup. Options 1–2 stay frozen as the original three-way comparison. Viewing as switches the same Option 3 page between HR Admin (Andrea Cruz, all 10 employees, Company tab) and Ramon Dela Cruz's Engineering/Design team (5 direct reports, Team tab) — per the user's call to reuse this one screen for both roles rather than build a separate Team page, row-scoped to reports only. Manual-edit permission and attendance approvers are company settings, so admin-only.

Why this one

Everything visible in one scroll, no clicks to reach either piece — a fair match for a feature the plan frames as small on both sides (a short template list, a comparison-only attendance flag). Reuses only components already decided elsewhere (stat-strip, cptable, toolbar chips) plus one new avatar-stack cell.

Trade-off

Gives a config table edited maybe once a quarter the same visual weight and page-top real estate as the list HR actually opens every day — and on a larger roster this page gets long before the attendance table (the part that matters most, day to day) even comes into view.

Cleanly separates two genuinely different admin tasks so each gets full width — shift cards get room for inline name/time editing, the attendance table isn't squeezed under a second header. Why this one

Matches actual usage frequency: attendance is what HR opens daily/weekly per the plan's own wording, shift templates are a "short company-maintained list" edited occasionally — so config sits one click away in a drawer instead of sharing the primary sightline. The Shift column tag on every row keeps the template→employee link visible without a second screen. Drawer shown open here purely for this comparison.

Trade-off

The drawer floats over the table rather than sitting beside it, so editing a template while cross-checking a specific attendance row means opening and closing it repeatedly; on a narrow viewport it would also cover most of the table width underneath.
