Add/Edit Job Opening — three recommendations

The form behind "New job opening" on Job Openings and "Edit opening" on Job Opening Detail — the actual first step of projects/hris/features/recruitment-ats/PLAN.md's core flow, "HR creates a job opening." Per the plan's own in-scope list this form is deliberately small: title, description, and open/closed status — no department, location, or employment-type fields invented beyond what's scoped.

Shown as the Edit case (fields prefilled with "Senior Backend Engineer") since it exercises every field at once; New job opening is the identical layout with empty fields, the header reading "New job opening," and the primary button reading "Create job opening" instead of "Save changes" — not rebuilt twice here. Uncheck each option's "Show open" box to see the Job Openings grid underneath. The application link (hris.app/apply/…) is auto-generated from the title and shown read-only, not user-editable — candidates apply there, not on a public job-ad page, per the plan's own scope correction. Status badges follow decisions/ui/badge-system-four-categories.md: Open reads Positive, Closed reads Neutral. Persona: Andrea Cruz, HR Admin, today is Aug 22, 2026.

Why this one

The sixth reuse of the same right-side drawer mechanic already established for Payroll Run Detail, Time & Attendance, Rate Tables, Loan Ledger, and Hired Handoff — HR already knows this interaction. More chrome than three fields strictly need — a centered modal would do the same job with less surface area. Worth it here for consistency with the rest of the admin surface rather than optimizing this one screen in isolation.

Why this one

Zero extra chrome — no overlay, no dimmed backdrop, editing happens exactly where the card already lives. Closest to "click, type, done" for a form this small, and the freshly created card appears in the exact spot it'll occupy going forward instead of being revealed after a drawer/modal closes.

Trade-off

Doesn't travel: this pattern only works from the Job Openings grid. "Edit opening" on Job Opening Detail has no grid to edit inline, so that entry point would need a completely different mechanic (a modal or drawer after all) — meaning HR learns two different ways to edit the same record depending on which page they're on. Also collides with the card/list view toggle already chosen for Job Openings; the inline form would need its own layout for the list/table view too.
