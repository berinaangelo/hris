Compliance / Certifications — three recommendations

The HR-Admin workspace under Company → Compliance (decisions/ui/navigation-me-team-company.md), built against projects/hris/features/compliance-certification-tracking/PLAN.md. Per that plan the scope is deliberately tiny — two fields (cert_name, expiry_date) per employee and one HR-facing list sorted by soonest-expiring. All three options below show that same single sorted list; what changes is only how urgency is surfaced within it, since restructuring the list itself (department rollups, a cycle/detail split, etc.) would be scope the plan explicitly doesn't ask for.

Ahead of the backlog, on purpose: compliance/certification tracking is post-MVP, customer-dependent (build only if a target customer has licensed staff) — this mockup exists to compare list shapes ahead of build. Viewing persona: Andrea Cruz, HR Admin. 10 certifications on file across 9 employees, today is Aug 22, 2026, notice window is a fixed 30 days (no per-cert configuration, per the plan). Per decisions/ui/badge-system-four-categories.md, a valid certification gets no badge — a badge appears only for Expiring soon (Caution, ≤30 days out) or Expired (Negative). No issuing body, cert number, or document upload — out of scope per the plan. No row detail, edit modal, or employee-facing view is wired here; this is a heads-up list, not an enforcement mechanism. All content shown is static, illustrative — this is a comparison mockup, not a wired form.

Why this one

The most literal read of the plan's own wording — "one HR-facing list, sorted by soonest-expiring." No new structure over that list, just the same table/toolbar/badge components already decided elsewhere in the app (people-directory.html, company-reviews.html). Filter chips and the search box are the only affordances added, both reused patterns, not new ones.

Trade-off

On a long roster, the two expired rows sit at the very top only because expiry sorts ascending — nothing visually separates "already lapsed" from "coming up," so a skimming HR admin could miss the line between them without reading the Status column.
