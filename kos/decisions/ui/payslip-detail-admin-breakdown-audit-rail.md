Chose "Breakdown + audit rail" for Payslip Detail (admin view) — the
HR-Admin screen for one employee's already-finalized payslip, reached
from a finalized row in
[[payroll-run-detail-master-table-edit-drawer|Payroll Run Detail]] or
from an employee's own payslip history — over a "Statement + action
bar" option (flat audit strip below the breakdown) and a "Document
preview" option (renders as the literal PDF/print document the
employee received). Full comparison, same Mikaela Santos / Aug 1–15,
2026 payslip on identical tokens:
https://claude.ai/code/artifact/c983a607-7b87-4081-a4d9-b395f98cded8

**Layout — the chosen option:**
- Crumb back to the originating payroll run; header with employee
  avatar/name/ID, cutoff, pay date, and a Finalized badge (Positive,
  per [[badge-system-four-categories]]).
- Left: the breakdown itself — pay-hero net pay figure, Earnings/
  Deductions two-column list, net pay total — reused verbatim from
  [[my-payslips-pinned-hero-swappable-table|My Payslips]]' own
  breakdown markup, since this is the admin's view of that exact
  record.
- Right: a persistent rail, three cards — Record (run link, generated
  date, generated by), Delivery (emailed timestamp, viewed badge), and
  Correction history (a small timeline of Voided/Current versions with
  reason and date per entry) — plus a fourth card of actions (Download,
  Resend email, Void & Reissue).
- No inline editing anywhere on this screen — a finalized cutoff's line
  items are locked
  ([[rails-db-transactions-locking-idempotency|locking + idempotency]]);
  a real correction goes through Void & Reissue, which opens a
  consequential-action modal (same pattern as Run Detail's Finalize
  modal) asking for a reason, marks the current version Voided
  (Negative badge), and creates a new editable version — the employee
  isn't notified until that reissue is itself finalized.

Built on tokens already decided elsewhere:
[[color-palette-ink-and-amber|Ink & Amber]] palette,
[[type-system-neutral-and-efficient|Archivo/Work Sans/IBM Plex Mono]]
type, [[badge-system-four-categories|four-category badges]], and the
same breakdown component as My Payslips.

**Carried over, not re-decided here:** same Mikaela Santos, EMP-0142,
Aug 1–15, 2026 cutoff shown on
[[my-payslips-pinned-hero-swappable-table|My Payslips]] — this is
literally the admin's view of that payslip. Figures are illustrative
placeholders, not real rate-table output — real amounts come from
[[../decisions/statutory-deductions-as-editable-data-not-code.md|editable
statutory tables]]; the loan line reflects
[[cash-advance-vs-loan-ledger-distinction]]. The correction-history
timeline is shown with one illustrative reissue (v1 Voided → v2
Current) to demonstrate the mechanism; a payslip never touched twice
shows an empty state instead, not designed in this mockup.

Why this one: payroll figures are exactly the kind of record that gets
disputed later — "why is this different from what I expected" — so the
who/when/whether-it-was-seen facts and the correction trail sit
permanently next to the numbers they explain, instead of being
something an admin has to reconstruct from a flat one-line strip
(Option 1) or go looking for elsewhere. Costs a fixed rail on every
visit, including the common case where a payslip was never reissued,
but that's a small, constant cost against the alternative of an admin
manually piecing together a dispute's timeline. Document Preview read
best for a support conversation needing to show "exactly what was
sent," but it's a second visual system built just for this one screen
— its own table style, own spacing — that this option and Option 1
both avoid by reusing the app's existing breakdown component; kept in
mind as a future addition (e.g. a "View as sent" toggle) rather than
the default.
